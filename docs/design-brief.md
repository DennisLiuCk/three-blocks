# Three Blocks — 設計簡報

> 本文件記錄專案啟動時定下的方向與原則,目的是先做出第一個能玩的版本,而不是一開始就把所有東西定死。

## 技術決策

- 引擎:Godot(GDScript)。
- 架構:邏輯與呈現分離,而不是前後端分離——規則跟呈現拆開放在 `rules/` 與 `presentation/` 兩個資料夾,但仍在同一個專案裡。

## 遊戲方向

- 一局 30–60 秒的決策型遊戲。
- 不是打敗其他玩家,而是挑戰規則本身。
- 遊戲的重心是讓玩家感覺「剛剛是我自己的決定」。
- 機率存在,但玩家可以影響機率,所以失敗比較像是「我剛剛判斷錯誤」,而不是「運氣太差」。

## 視覺原則

- 盡量用圖像跟動畫取代文字,讓規則被看出來,而不是讀出來。

## 第一版(MVP)範圍

- 三種選擇、五回合、立刻給回饋。
- 成功的指標不是功能齊全,而是玩完一局會不會想再來一局。

## 目前實作狀態

`rules/` 是不依賴場景樹的規則層,可以獨立閱讀、之後也可以獨立測試:

- `round_option.gd` — 單一選項的資料:id、風險(risk)、報酬(reward)、視覺大小提示(size_hint)。
- `game_rules.gd` — 每回合產生三個選項(風險/報酬隨回合遞增),並依「基礎風險 − 玩家影響力」計算成敗。
- `run_state.gd` — 單局進度:目前回合、分數、歷史紀錄。
- `game_session.gd` — 串起以上三者,用 signal(`round_ready` / `round_resolved` / `run_ended`)對外廣播狀態變化;呈現層負責訂閱,並自行決定節奏(例如動畫播完才呼叫 `advance()` 進下一回合)——節奏是呈現層的事,不是規則層的事。

`presentation/main.gd` 是暫時的佔位呈現(尚未在 Godot 編輯器中實際開啟測試過):

- 三個方塊依風險上色(越紅越危險)、依報酬放大,用大小與顏色取代文字說明。
- 玩家按住方塊「蓄力」,放開的時機決定影響力(太快或太久都會降低影響力,抓到甜蜜點影響力最高)——這是玩家能實際練習、變準的技巧,而不是單純的機率賭注。
- 方塊依成敗閃綠或閃紅,並有縮放動畫做立即回饋。
- 五回合都會玩完,結束畫面顯示成功次數與再來一局的按鈕。

## 待決事項(下一步)

文件本身最後標記了三個「下一步需要定」的問題。目前的實作只是暫定的預設值,尚未定案,一旦定案,之後加任何玩法或特效都會更一致:

1. **每回合玩家到底在做什麼決定?**
   目前預設:選一個風險/報酬不同的方塊,並用按住蓄力的時機影響成功率。
2. **玩家追求的是什麼?**
   目前預設是「軟失敗」——五回合一定會玩完,單次失敗只是那一回合沒加分。另一個方向是「硬失敗」——任何一次失敗就結束整局,張力更高,更像典型的 push-your-luck 賭注,但也可能讓手氣差的玩家很快就結束、體驗不到完整五回合。這個取捨需要定案。
3. **這個世界的視覺隱喻是什麼?**
   目前是抽象的「風險方塊」:大小代表風險/報酬、顏色代表危險程度,沒有敘事包裝。可以維持這種抽象幾何風格,也可以換成更具體的隱喻(例如疊塔、天秤、反應爐過熱等),讓「規則被看出來」這件事更有記憶點。
